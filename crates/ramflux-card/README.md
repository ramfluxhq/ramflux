# ramflux-card

Interpreter-only in-chat form runtime. This crate has no SDK dependency, network,
storage, native views or approval authority. `rf-card/v1` is a dormant local
renderer profile; it does not activate or change the wire Surface catalog.

The host validates `CardSpec`, verifies `SignedPackage` against its release-pinned
Ed25519 key, and opens a `CardSession` on a dedicated renderer thread. Each VM uses
QuickJS-NG 0.16.2 via exactly pinned rquickjs/core/sys 0.14.0, 32 MiB engine heap,
256 KiB stack, a 50 ms evaluation deadline and a rolling 100 ms/second budget.
There are at most two resident VMs per linked crate instance, 32 queued events per
session, and 128 evaluation admissions per second. The heap budget is not an RSS
limit or an OS sandbox. WASM must run in a dedicated worker; `web-time` requires
the browser monotonic clock. No engine values leave the owning thread.

The context has JSON and Promise intrinsics, with **no Eval intrinsic** and no
module loader. The sole host function is immutable `__rf_commit`. A signed module
exports synchronous `render(inputJson)` and must commit exactly once per render.
The project library parses and freezes its selected form input. Rust validates
the entire committed tree before publishing any keyed mutation. Unknown controls,
props, duplicate keys, invalid bindings and security chrome are refused.

Input is limited to 16 KiB, 32 forms, a 4 KiB string model, depth 16 and 256 expanded
nodes / 64 KiB output. This first component has one text field per form; pointers
are restricted to one local object property. Forms cannot share a binding.
Strings are plain text, never markup. Submit returns only that form's validated
field and action. The SDK must independently resolve the owning Surface, peer,
authority, exact arguments and receipt; renderer events cannot authorize a send.

Every accepted snapshot, edit, submit, suspend and resume advances a monotonic
tree version. Tokens also carry a process-unique session ID. Stale and foreign
session tokens are dropped at dequeue. A submit consumes its displayed version.
Suspension clears queued events, removes the tree and releases the VM. Resumption
mounts a complete tree under a fresh version. Evaluation failure disables the VM;
the host must replace the mounted controls with its native fallback on any error.

## Project library and signing

Run `npm ci && npm test && npm run build && npm run check` in `library/`. The
esbuild pipeline bundles only `form.tsx` and uses an AST lint for eval, Function,
dynamic module loading, network/storage APIs, prototype access and computed
property escapes. Source is project-controlled; the lint is defence in depth,
not a general-purpose JavaScript capability proof. Peers provide JSON only.

Use the offline compiler after the build lint:

```sh
cargo run -p ramflux-card --example card-pack -- \
  crates/ramflux-card/library/form.js /secure/release-seed /release/form
```

The compiler uses Eval only to compile the project source. It writes little-endian
`.qjb`, detached `.sig` and `.pub`. Never distribute the seed or accept a package's
public key as trust. The signature domain includes engine/version/host identity
and the complete bytecode. Applications ship the package and pin its public key;
there is no default development key, OTA loader or peer-source compilation API.
Engine upgrades require regenerated bytecode, signatures and fixture checks.
The application release controls rollback; this crate has no independent update
channel. Desktop, mobile and WASM use this same validator/runtime.

## C bridge (optional `c-abi` feature)

`include/ramflux_card.h` defines standalone card symbols for inclusion alongside
the SDK v2 header. Link this rlib into the SDK's existing static/dynamic library;
do not introduce a second Rust static runtime. The C ABI does not expose an SDK
client or change SDK default features. All six calls are synchronous and bounded;
there is no detached work or cancellation handle to retain.

Handles are process-unique u64 values, owned by the creating renderer thread.
At most 32 sessions can be retained on one thread; only two may have resident VMs.
Invalid, disposed or foreign-thread handles return 7. `dispose` drops all owned
state. Callbacks are mandatory, execute on that thread before return and receive
borrowed UTF-8 JSON `{session,payload}`. Copy it before posting to a native UI
thread. The callback must return normally and must not reenter (status 8). No
callback/user pointer is stored. Inputs are borrowed only for the call and copied
within explicit byte limits. `open` zeros its output slot on failure.

Update/suspend/resume/open payloads are mutation batches. Event payloads are
`stale_dropped`, `edited {batch}`, or `submit {action,fields,batch}`. Event JSON is
`{token:{session,version,key},event:{kind:"text",value:"..."}}` or
`{token:{session,version,key},event:{kind:"submit"}}`. Each upsert is shallow:
apply removals first, then ordered parent-before-child upserts at the stated
sibling indices. Removing a parent removes its entire native subtree. Hosts must
refresh tokens for the complete tree whenever a batch advances the version,
even if its mutation list is empty. Never dispatch events while a session is
suspended or after an error.

Status codes: 0 success, 1 invalid input/JSON, 2 resource limit, 3 package signature,
4 engine, 5 evaluation budget, 6 inactive, 7 invalid handle, 8 reentry/busy.
Success invokes one callback; errors invoke none. FFI callers must supply valid
aligned pointers and readable byte spans; arbitrary invalid pointers are outside
the C contract. No panic recovery or unwinding across the C boundary is used.

## Checks

`cargo check -p ramflux-card --all-features`, `cargo test -p ramflux-card
--all-features`, and `cargo clippy -p ramflux-card --all-targets --all-features --
-D warnings`. Cross checks use `--target wasm32-unknown-unknown`,
`aarch64-apple-ios`, and `aarch64-linux-android`. Mobile targets enable bindgen and
require libclang and their platform SDK/NDK. WASM uses a WASM-capable clang.
Fixtures test actual compiled and signed bytecode, tree/mount/edit snapshots,
resource exhaustion, stale events and lifecycle ownership. They do not establish
native UI, device or end-to-end SDK acceptance.
