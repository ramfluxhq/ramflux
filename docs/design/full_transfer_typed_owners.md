# Full-transfer typed owners

Implementation contract for PRIMARY-TRANSFER-PROOF-01, controller decision r2.
The approved support envelope is 71 previously incomplete SQL declarations and
public agent metadata. Seventeen optional/history declarations remain refused.
The [source census](full_transfer_owner_census.md) records field assignments,
literal SQL writers and conservative actor call sites at checkpoint 0. It is a
worklist, not evidence of complete semantic implementation. Each activated owner
must replace its placeholder, update its codec version and have storage witnesses.

## Admission and versions

Unknown tables, actor variants, nested fields and secret-bearing signed documents
refuse before invitation. Null/excluded fields do not bypass an incomplete owner.
Never remove source rows to pass preflight. Local diagnostics may name only a
compiled category; the remote error remains the existing typed error.

The source checks its complete compiled census and codec versions before Issue.
A capability token alone does not establish peer agreement. The recipient must
compare the authenticated source census commitment with its own catalog during
join/data preflight, before accepting portable records or permitting any candidate.
A new recipient does not exist at source Issue; no claim of peer comparison before
that invitation is made. Carry the commitment through the full-profile authenticated
exchange and reject before data application. Mismatch returns
SchemaMismatch; absent required profile returns UpdateRequired. No protobuf,
message descriptor or C ABI changes are authorized. If the existing invitation
exchange cannot carry that commitment without expanding a separately pinned
surface, stop and report the exact boundary before changing it.

Do not reinterpret old stage chunks. Before possible publication, mismatched
stages require a new attended ceremony with matching builds. After possible
publication, reconcile the exact retained candidate; retain InstallPending and
ordinary-session fencing when its installation format is incompatible. Never
roll back publication or silently complete/abandon an outstanding tail.

## Portable records

Every owner provides a bounded source encoder, independent receiver validator,
restriction-first union, derived-state rebuild and real-storage semantic witness.
Encoding a SQL row's physical types alone is not a typed semantic owner.

Keep signed Inner/envelope/native bytes exact and retain their original qualified
source and MAC association. Own-authored history is its own evidence class; do
not invent peer-origin evidence. Preserve pending authored content before dropping
courier execution state. Imported journal/results/permissions are inert history;
no old request, grant, control, callback or retry is activated on B.

Erasure, revocation, denial, replay and ambiguous-copy restrictions precede content
in base, reverse, delta and tail merges. Equal immutable identities with different
bodies refuse TransferConflict. Maxima apply only within the same qualified
issuer. Absent removes A's contribution, never B's independent contribution.
Rebase against B's current generation and recheck erasure before selection.
Rebuild nested copy locators and last-owner edges transactionally; one erased
owner invalidates a multi-message history container.

Group history retains validated genesis, membership epoch and control evidence.
Keep content-decryption keys in a receive-only historical namespace; do not import
sender chains or private signing state. Missing evidence blocks affected mutation.
Object metadata includes remote retrieval references, exact manifests and content
keys, but no source path/ciphertext/cache progress. Grants remain inert. Ordinary
B authorization owns retrieval/rewrap; local-only live attachments return
AttachmentNotRemote until normal upload completes.

The fixed-width encoder/union's small scratch and bounded row spool are not generic
history limits. Variable records must use bounded streamed/encrypted owners with
checked offsets, counts and disk quota. No unbounded peer-sized allocations and
no plaintext temporary files. Do not raise limits without implementing the owner.

## Public agent file cut and installation

Input owners are SDK AgentRecordStore and the public projections of
AgentCreationStore/rebind inventory. The transferable shape contains agent and
custodian anchors, persona/access policy, role, EventIdentity, retired lifecycle,
public profile/receipt evidence and public pending rebind intent. Exact public
signature bytes stay exact. Local watch sequence/change cursor is rebuilt.

Never transfer source account IDs as executable selectors, approved/pending
creation state, decision capabilities, transport outbox, master/vault references,
provider handles, private keys or recovery material. A public receipt is historical
evidence, not permission to resume its executable request. Conflicting public
agent identity or immutable receipt refuses; retirement/denial dominates.

Source public metadata writes and the source snapshot cut must share a serialized
owner. Project the closed public records into the encrypted cut while that owner
is held; release it before encoding or network work. Every base/delta/tail uses
that same view. A loose traversal of files after pinning the database is forbidden.
Unknown/corrupt files refuse; never import arbitrary paths or a directory tree.

On B, import into a private generation under its writer fence, merging current
B metadata and retirement state. The generation recovery manifest must bind the
public metadata generation/root to the selected DB and expected native head.
Fsync private data, select it with the account generation and require installed
marker agreement before readers open. Every gap remains fenced on restart;
recovery finishes the exact selected generation. Do not write live agent files
after selecting the database and then claim atomic installation.

The agent remains visible with its public metadata after transfer. Its runtime
is paused as rebind_pending until the original desktop sends the signed request,
the new primary approves, and matching agent/profile publication receipts arrive.
Offline/denied approval remains pending; missing protected master is
custody_key_unavailable. No automatic replacement agent or widened permission.

## Deferred categories

The seven legacy families in the census are not converted or supported. Their
current writers remain for the separately assigned removal module. Bot/MCP
permission/configuration, public recovery history and audit history likewise
remain UnsupportedRecord when present. Accounts containing any such records
cannot transfer under this support envelope. Empty deferred families do not
block otherwise supported accounts. No automatic deletion or selective export.

## Internal checkpoints and proof

0. Freeze field/write-site census, public-file cut/install contract and version
   refusal rules. Do not activate undeclared codecs.
1. D1 content, contacts, raw provenance, ordering and erasure: encrypted real-storage
   round trips, independent B restrictions, nested-copy rebuild and restart.
2. Group owners: genesis/epoch validation, bans/removals and fresh B sending.
3. Object owners: key/reference graph, remote retrieval, grant refusal and erasure.
4. Daemon/identity, nested card history, public agent owners and fenced installation.
5. Existing process harness with real services/daemons and product CLI; automatic
   couriers, normal-account data, send/receive after transfer, source demotion,
   node authority, private-key exclusion, cancellation, abandonment and restarts.

One module and one PR. Commit each checkpoint. Open the PR after checkpoint 1;
keep it unready until checkpoint 5 and exact-head CI are green. Tests use semantic
barriers/bounded deadlines. No fixture-only or manually driven courier success
stands in for the process proof. No deployment or test-node operation by this lane.

## Contact denial owners

The shared metadata row resolver uses compiled composite keys and explicit bounded
SQL text/enum/integer codecs. It does not accept generic JSON or signed payloads.
Message fence retention takes the later deadline, retirement takes the later retry
bound, and request fences keep the stronger state (blocked over declined) and an
indefinite lifetime (zero) from either contributor. These unions never lift consent.
A retained message deadline without its contributor's matching fence, or a timed
fence colliding with an independently untimed fence, refuses TransferConflict
before DataVerified. This stricter choice avoids assigning an expiry to an
independent denial; no wall-clock guess or fabricated deadline repairs the rows.
