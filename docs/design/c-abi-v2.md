# C ABI v2

The default-off `c-abi` feature exports `ramflux_v2_*` alongside the unchanged v1
symbols. Link the SDK static library on iOS and the shared library on Android.
Mobile targets bundle SQLCipher's OpenSSL dependency; their system SDKs do not
provide libcrypto. Desktop target dependencies are unchanged.
The header is generated by cbindgen from the Rust exports into
`$CARGO_TARGET_DIR/include/ramflux_sdk.h`; the reviewed copy is
`crates/ramflux-sdk/include/ramflux_sdk.h`. Generate it with
`cargo check --locked -p ramflux-sdk --features c-abi`, then run
`python3 scripts/check-c-abi-header.py`. The build pins cbindgen 0.29.4 and LF
line endings; do not regenerate with an independently installed cbindgen CLI.
CI compares the generated header with the committed copy byte for byte after
all-features Clippy. Generation or write errors fail the build. Define `RAMFLUX_WITH_CARD_RUNTIME`
when building with the optional `card-runtime` SDK feature to include its independently owned
`crates/ramflux-card/include/ramflux_card.h` as well. The `ramflux_card_*` session
symbols belong to that crate; sessions are renderer-thread-affine u64 tokens,
and callback JSON is borrowed only for the synchronous callback. Card events
produce declarative intents; SDK authority validates and signs any send.

## Notification-extension host

[`ramflux_v2_wake_fetch`](wake-fetch-host.md) runs one bounded authenticated inbox
fetch for one account using shared custody and the notification-priority session
lease. It does not open a full client or start background workers. Its typed
outcomes are `fetched`, `busy`, `locked` and `deadline`; transport receipt does
not imply durable application, ACK or a notification result.

## Negotiation and requests

Call `ramflux_v2_negotiate(2, 0, &buffer)` before opening a client. Negotiation
returns the binding major/minor, BLAKE3 fingerprint of the message descriptor,
carrier protocol, operation inventory and limits. Binding version and message
schema version are independent. A major mismatch or a newer minimum minor
returns UnsupportedVersion (3). A host must compare the descriptor with the one
its typed message binding was built against.

`client_open` accepts I-JSON `{ "data_root": "/absolute/private/path",
"builtin_nodes": [] }`. It creates one current-thread supervisor and acquires
the existing data-root writer lease. A second opener of that root fails. No
pathname listener is created, and neither the CLI nor its daemon is modified.
Opening and closing block: invoke them on a native background executor.

App and extension hosts can opt into [shared-root session handoff](shared-root-session-lease.md)
with `"session_lease": {"priority":"notification", "wait_ms":5000}` in either
v2 open configuration. Priorities are `foreground`, `notification` and `background`;
the wait defaults to five seconds and cannot exceed it. A pending request drains
the old supervisor before releasing its lease. Contention returns AccountBusy (18).
After yielding, close the old handle and open a fresh client before further work.

`execute` copies this bounded request and returns an operation handle immediately:

```json
{
  "account_id": "local-account",
  "sdk_api": "account",
  "method": "account.status",
  "body": {},
  "deadline_ms": 1794571200000,
  "operation_id": "caller-owned-durable-operation-key"
}
```

`account_id` and `operation_id` may be absent. `deadline_ms` is required and is
absolute Unix milliseconds. `body` is the existing SDK bus method's request
body; it is not a second business schema. Message ProtoJSON retains its own
schema's presence and decimal string rules. The bridge never generates an
operation key, retries a mutation or turns a lost response into success.

## Attended account code

`ramflux_v2_set_credential_provider` installs the callback that answers
`device.credential.request` on the in-process connection. Setup requires the
code twice and the copies must match. Unlock and phrase take one copy and an
empty confirmation. A null callback unregisters and drains. The host must not
reenter the client from the callback. Close and replacement wait until the
callback returns. `account.passphrase.rotate` stays in the wiped request body.

## Generated method policy

`crates/ramflux-sdk/include/ramflux_sdk_methods.json` is the machine-readable
native binding policy. Each row has `name`, `capability`, `secret_input`,
`secret_output`, `show_once` and `key_export`. Capability is the SDK operation namespace used
for discovery, **not** an authorization grant. Secret flags conservatively mark
confidential payloads/credentials; they never authorize logging other bodies.
`show_once` describes the SDK's one-time phrase-disclosure operations.

The source of truth is the explicit Rust registry
`src/c_abi/v2/method_policy.rs`. Run
`python3 scripts/generate-c-abi-methods.py` to regenerate the checked artifact,
or pass `--check` to detect drift. The feature-enabled build also generates the
same file beside the cbindgen header in `$CARGO_TARGET_DIR/include/`.
`every_operation_has_explicit_policy_and_generated_manifest_matches` compares
policy names against the live SDK method table, custody operations and backup
job methods, and compares all flags with the generated JSON. A new operation
without a policy row fails this test. Negotiation includes this same manifest
under `method_policy`, with `policy_version = 2`.

connection-local custody ceremonies. Every admitted request passes through the
same connection dispatcher and supervisor used by the CLI, including authority,
account actors, lifecycle receipts and writer ownership. Integration-fixture
methods are rejected. Operations currently cover:

the bridge does not implement parallel business handlers.
Card interpreter sessions are owned by the card-runtime module and must be
linked with the SDK in the same mobile library; surface operations here are the
SDK's existing surface delivery operations.

## Completion, cancellation and ownership

Handles are opaque nonzero `uint64_t` tokens; they are never addresses. There
are at most 16 open clients and 64 retained operations per client. Every
operation owns terminal reply credit independent of the event queue.
`operation_poll` returns Pending (24) with a null buffer, or 0 and a JSON
completion `{ "code": 0, "response": <complete SDK response frame> }`.
A nonzero completion `code` is a business failure; the original response error,
reason, details and retry hints remain intact. Polling does not consume a
completion; call `operation_release` exactly once after inspecting it.

The operation token is also its explicit cancellation handle. `operation_cancel`
marks a cancelled waiter. If cancellation wins the locked admission transition,
the worker emits `{ "code": 25, "effects": "none" }` without writing the
request to the dispatcher. After carrier admission, cancellation does not stop
or roll back execution; poll for its result, or release the waiter and reconcile
the original operation key. Lifecycle work and receipts remain supervisor-owned.
Release detaches the native waiter; admitted work retains internal credit until
its terminal response. Discarding a Swift Task or Kotlin Job is not cancellation.

Each nonnull output is a `RamfluxBuffer` owned by the caller. Read exactly `len`
bytes, then call `ramflux_v2_buffer_free` exactly once, including for errors and
secret ceremony responses. It erases the allocation. Do not use the v1 free
function for v2 output. Input remains caller-owned and valid until the FFI call
returns. Temporary encoded requests and retained completions are erased on drop.

`client_close` stops admission and asks the owner thread to disconnect, drain
its supervisor, close stores and release the writer lease. Call it off the UI
thread. The first call waits up to ten seconds and returns Timeout (10) if the
owner has not confirmed completion. The handle and operation completions remain
valid. Further calls poll the retained shutdown state: Pending (24), confirmed
Done (0), or the same cached terminal SDK error. New execution is refused once
close begins, and the real data-root lease refuses a replacement writer while
shutdown is pending. Only confirmed success removes the handle automatically.
Repeated close after confirmed success is harmless.

A terminal shutdown failure remains available on the same handle; after the
host has inspected/reported it, `client_release` explicitly discards the retained
handle and completion state. It returns Pending (24) and retains the handle if
shutdown is unfinished. It never interrupts the supervisor or grants ownership
to a replacement. Stop submissions and event pumps before closing; a lost reply
still has unknown business effects.

## Events and errors

The cbindgen header declares `int32_t ramflux_v2_event_reset(uint64_t handle, uint64_t subscription_generation)`.
It clears the latched gap and buffered stale events for that generation after
the host has rebuilt its projections. A stale generation returns
InvalidArgument (1) and leaves the replacement queue intact. Use 0 only before
the first successful subscription. Cancel the old subscription, await an explicit
`subscription.close` acknowledgement, read the snapshot, reset, then subscribe
from that snapshot's journal cursor. Reset does not fetch data or restore a
subscription by itself.


Open the account journal via `execute` using `bus.subscribe`. `subscription.open`
remains the ephemeral, backup, pairing, and attended-frontend opener. A journal
topic, including `*`, is refused on an open account. Phones do not use it to
tail the journal.
`event_poll` consumes one frame without blocking. It returns Pending (24),
Closed (26) with a null buffer. ResyncRequired (27) includes an owned, generation-tagged gap event. Event
credit is bounded to 64 frames and 4 MiB; a single frame is at most 1 MiB.
Overflow clears stale events and latches ResyncRequired. Cancel the old subscription and read current projections, call
`event_reset(handle, old_generation)`, then subscribe from the snapshot's journal cursor; never treat
a gap as a continuous stream. The subscription operation token is its cancellation handle: cancel/release sends
`subscription.close` through the shared dispatcher. Each client owns one active
subscription; cancel it before opening another. Closing also cancels it.
Completions continue independently when event credit is exhausted.

Immediate statuses use existing numeric `RamfluxErrorCode` values 0–23,
including AccountBusy=18 and SchemaResetRequired=23. V2 adds Pending=24,
Cancelled=25, Closed=26 and ResyncRequired=27 without changing v1. Unknown
business error names map to Internal=16 while preserving the full typed SDK
error frame. Attachment refusals, including `authority_unavailable`, map to
InvalidArgument (1); the error frame still carries the stable code string.
Native code must inspect numeric codes, not diagnostic prose.

Host pointers must be aligned and valid for their documented lengths. Null,
invalid lengths, duplicate I-JSON members and invalid handles are rejected.
Foreign callers must never pass dangling pointers or double-free buffers.

## Subscription generations

Each successful `subscription.open` / `bus.subscribe` completion carries
`subscription_generation` both beside `code` and in its original response
frame. Every event frame carries the same field. It is an exact decimal JSON
string representing a nonzero u64. Allocation is process-wide, so each
account's generations strictly increase across close/reopen (gaps are valid).
Zero means there was no matching subscription and must never be presented.

The dispatcher snapshots the generation into each outbound producer. Cloned
old producers retain their old generation even if they enqueue after a newer
open completes. All producers still share the original bounded 64-frame queue;
there are no additional per-generation queues. **Hosts drop frames whose
generation != current**, and still validate the expected account. Adopt a new
generation only from a successful open completion. Reset carries the generation
as its second C argument; an old callback cannot clear a newer subscription.

A successful reopen discards old buffered events and the old overflow latch.
Late old events remain tagged old. Overflow caused by a stale frame cannot
invalidate the replacement stream. ResyncRequired (27) returns an owned,
tagged `stream.lagged` event buffer; free it with `ramflux_v2_buffer_free` even
though the status is nonzero. Pending/Closed return null buffers.

`real_dispatcher_preserves_old_generation_after_close_and_reopen` opens the
actual supervisor backup stream, closes/reopens it, then delivers through an
old producer and the real wire writer/decoder. `stale_event_reset_cannot_clear_a_replacement_subscription`
checks the C ABI open completions and rejects a stale reset after reopening.

## Shared client projections

`ramflux_v2_conversation_project(input, len, &out)` calls
`ramflux-client-model::conversation::{page,totals}`. Input is a host-owned
snapshot: `rows` (id, title, optional preview/pinned/latest_ms/unread/attention),
`visible`, optional `query`, `offset` and `limit` (default 100). Output has the
projected rows, `next_offset` and snapshot `totals`. Locked/inaccessible snapshots
set `visible:false`; the shared model clears rows and totals. Its page limit is
100, query limit 1024 bytes; the binding also bounds input to 4096 source rows
and the common frame/value budget. List filtering remains a pure projection.

`ramflux_v2_receipt_present(input, len, &out)` calls the shared receipt
`present()`. Input has `outgoing`, `now_ms` and `receipt`, for example
`{"outgoing":true,"now_ms":"123","receipt":{"state":"sent"}}`.
States are sending, waiting_for_node (retry_at_ms), failed (retryable), sent,
delivered, read. Output is null for incoming messages, otherwise receipt,
manual_retry and remaining_ms. Acceptance never becomes delivery/read because
of time; uncertain outcomes never gain retry permission.

Clocks/offsets accept exact decimal strings (safe JSON numbers are also
accepted); u64/i64 output quantities use decimal strings. Both entrypoints run
without a client handle, use the common buffer ownership/error contract, and
serialize confidential snapshot data. They retrieve no data and confer no SDK
authority. Business models and policy stay in the shared crate.

## Conversation send

Use `conversation.send` through `ramflux_v2_execute`, with an account id, a durable
`operation_id`, and body `{conversation_id,text,prepares?,media?,group_id?}`.
Text is UTF-8 and uses the generated Message byte limit. Prepared files use
`prepares`: an array of `{prepare_id}` from `attachment.prepare.finish`. An empty
`prepares` list falls through to prebuilt `media`. Each media reference contains
the ATTACH-LARGE-01 r4 `large_manifest`. A non-empty `attachments` field is
retired and returns Content
(`retired conversation attachment input; use media with r4 large_manifest`)
before route or network work. Mixing non-empty `prepares` with non-empty `media`
returns `layout_invalid`. Routing fields are refused.
The SDK derives the sender from its authenticated device. A group send passes
`group_id`. Sealing, friend-link checks, TTL, own-device copies and gateway
submission use the existing SDK delivery paths. DM and group media use the same
generated Message contract.

Finish also accepts optional `width`, `height`, `duration_ms`, and `animated`.
Width and height must appear together, each in 1–32768 pixels. Duration is an
unsigned u64 millisecond count: use an exact decimal string (safe JSON integers
are also accepted). Zero duration and `animated:false` retain explicit presence;
absent values mean unknown. Accepted metadata and poster are immutable on replay.
These are client-supplied hints; the SDK neither decodes nor transcodes the body.
The encrypted layer-5 `MediaRef` carries fields 9–12 in that order, preserving
`inline_thumbnail` as the M1 poster. Message reads expose ProtoJSON `width`,
`height`, `durationMs` (decimal string), and `animated` after reopen. No metadata
is published to the relay. Bindings must pin the new descriptor. Unknown media fields are never silently
dropped by the canonical scanner.

The call returns the usual asynchronous operation handle. Its completion body has
`message_id`, `conversation_id`, `delivery_state` (`submitted` or `failed`), and
per-target `deliveries` with stable error codes on failure. Submitted means gateway
submission, never delivery or read. Use existing receipt/event projections for later
progress. Fan-out preserves the first local ciphertext and refuses a changed sender,
conversation or plaintext under that logical id. The response message id is the allocated qualified event identity; the account and
operation id select its durable retry record, so retries retain that identity. Existing operation reconciliation governs interrupted mutations;
a failed fan-out can have partial effects and is not a no-effects cancellation.
Before a verified route is available the operation can return the usual SDK error.

`message.submit` is disabled in v2 by default (PermissionDenied=12 before admission).
Trusted diagnostic hosts can open with `allow_raw_messages:true`; its generated
capability is `raw_message`. Native product clients use `conversation.send`.

## Large attachments

Large files stay disabled until an explicit enable. Account activation does not
enable them. Call `attachment.enable` once per account with `{from_node:true}`
after the home node is live. The SDK reads the home relay authority through the
live gateway and pins it. A later different pin is `duplicate_operation`. Until
that pin exists, `attachment.prepare.begin` returns `large_attachments` (C ABI
numeric code InvalidArgument = 1). A peer that imports a remote file must enable
the same way: remote import reads the pinned authority.

`attachment.prepare.begin` takes
`{operation_id, kind, file_name, mime, path?}`. A direct message sets `kind` to
`dm` and `peer` to the conversation id. A group sets `kind` to `group` and
`group_id`.
The response includes `prepare_id`, `generation`, `state` (`accepting` when new)
and `max_chunk`. Stream plaintext with `attachment.prepare.chunk`
`{prepare_id, generation, offset, data_base64}`. `data_base64` is unpadded
URL-safe base64, and each chunk is at most 512 KiB. Finish with
`attachment.prepare.finish`
`{prepare_id, generation, plaintext_length, plaintext_digest}`.
`plaintext_digest` is the lowercase hex BLAKE3 of the plaintext bytes with no
domain separator. Finish optionally accepts
`thumbnail: {mime_type, width, height, encoded_image_base64}`: JPEG or WebP,
1–320 pixels in each dimension, 1–16384 encoded bytes, unpadded URL-safe base64.
The SDK checks the image container and its actual dimensions against these fields;
clients remain responsible for safe pixel decoding. Invalid thumbnails return
`layout_invalid` before any relay reservation. An accepted finish is immutable:
retry with the same digest, length and thumbnail; changed metadata returns
`duplicate_operation`. Omit `thumbnail` for no preview. The exact thumbnail
persists across reopen and appears as `inline_thumbnail` in `message.read`,
inside the encrypted message, before any `attachment.import.*` body fetch.
Thumbnail bytes count toward the encoded message size before upload; a valid
thumbnail can still produce `manifest_too_large` for an oversized message.
Then `conversation.send` the `{prepare_id}` values.

Import the peer's bytes with `attachment.import.begin`
`{message_id, index, operation_id}`, poll `attachment.import.status`
`{import_id}` until the view is ready, read with `attachment.import.read`
`{import_id, generation, offset, max_bytes}` (`1 <= max_bytes <= 524288`; the
response `bytes` field is the same base64url, plus `eof` and `offset`), and
finish with `attachment.import.finish` `{import_id}`.

## Host custody provider (Android M4 and iOS)

`ramflux_v2_client_open_with_custody` accepts the same JSON config plus a version-1
`RamfluxV2CustodyProvider` table. It adapts host OS storage to the SDK's existing
`PrimaryVault`; account create/recovery/pairing remain SDK ceremonies. M4 supplies
Android Keystore wrapping and JNI attachment on callback threads. An iOS host can
supply Keychain storage through the same seam. Ordinary open keeps the existing
native provider selection; there is no file or data-passphrase fallback.

The provider must be non-synchronizing, device-local and independent of data unlock.
Primary and branch entries are separate. Store operations are create-only, refuse
an existing reference, and complete only after durable protected storage; delete is
idempotent. References are opaque canonical SDK references, not filesystem paths.
The provider's preflight runs before recovery material is shown. This seam grants
no independent user-presence authorization: migration signing remains fail-closed.

The header defines operations and callback status values. Primary bytes are a
32-byte vault seed; branch bytes are 64-byte signing/agreement seeds; provisioning
bytes are bounded to 4096. Store inputs and load outputs are secret and must never
be logged, persisted in ordinary preferences, or exposed to application observers.
All callback buffers are borrowed for the synchronous invocation only. The SDK owns
and erases its output buffers; hosts must erase temporary copies. Output lengths
are validated before decoding and key lengths must match exactly.

The table is copied during open. All callbacks are mandatory and may run on SDK
worker/blocking threads, including concurrently; attach to the host runtime as
needed. Callbacks must be bounded, must not unwind, and must not reenter this client.
`retain(context)` occurs once after table validation; `release(context)` occurs
once after the final SDK task drops the provider, including failed startup or a
shutdown that initially timed out. Keep callback code loaded until release. Pending
close retains context; confirmed successful close has drained its tasks. Context is
an opaque 64-bit host token; the SDK never dereferences it.

## Optional renderer linkage

Build `ramflux-sdk --features card-runtime` to include the accepted `ramflux-card`
rlib and its C exports in the SDK library. This enables SDK `c-abi` as well;
ordinary `c-abi` builds omit the renderer. Package one Rust library and both
headers, and define `RAMFLUX_WITH_CARD_RUNTIME` when consuming the umbrella header.
Negotiation returns `card_runtime:null` when disabled, otherwise the independent
card ABI major and catalog SHA-256. Always check `ramflux_card_abi_version()`
before passing card structures. The accepted runtime and library use standalone
card ABI 4; SDK ABI 2 numbering is independent. `RamfluxCardOpen.presentation` is
mandatory. `ramflux_card_present` switches host locale/theme without a peer update.

`RamfluxCardOpen.descriptor` authenticates application/package identity, catalog,
engine, ABI, epoch/version and exact bytecode digest. Its separate `policy` and
trusted key come from the embedding application's pinned release configuration,
never peer/package input. All card calls remain on their creating renderer thread;
callback bytes are borrowed only during the synchronous callback. Card statuses
remain their own 0..8 namespace. Declarative intents confer no SDK authority.

## High-level message mutations

Use `sdk_api:"conversation"` and `ramflux_v2_execute` for these operations. Each
requires the account id, a nonempty `operation_id` (at most 256 bytes), and a body
with `conversation_id` and the existing `message_id`:

| Operation | Additional body fields |
| --- | --- |
| `conversation.edit` | `text` (1..65536 UTF-8 bytes), a complete text replacement; `expected_revision` (u64), the base revision the caller observed. Required. A missing field is `invalid_argument`. A mismatch, or a base another local edit has already reserved, is `edit_conflict` (body code 7, details `{target, expected, received}`) and is not sent. |
| `conversation.react` | `token` (SDK-validated reaction), optional `remove` boolean |
| `conversation.reply` | `text` (1..65536 UTF-8 bytes) |
| `conversation.delete` | `scope`: `local` or `everyone` |

The SDK reads the authenticated stored target identity and derives its author,
reference, edit revision and exact previous-content digest. It applies the shared
author/moderator rules, allocates one durable source-qualified event identity and
private revision entropy, and uses SDK routing/sealing and ordinary group or
verified peer-device fanout. Hosts cannot supply a sender, device, envelope,
written revision, digest or tombstone. `expected_revision` is the observed base,
not the revision the edit will write. Unknown fields are refused. An edit replaces
the whole Message content; old reply, media and forward fields are omitted.

Retries with the same operation id retain the exact prepared Inner and identity;
changing the intent under that id is refused. Private prepared content is owned
by the target's erasure lifecycle. Network operations return `event_id`,
`target_message_id`, the SDK local `message_id`, per-target outcomes and
`delivery_state`. Submitted outcomes do not mean delivered/read; authoritative
message changes still arrive through the existing SDK projection/event path.
A local delete applies the shared local-account deletion and returns
`delivery_state:"local"` with an empty deliveries list; it never fans out to peers.

These structural operations obey the existing message-schema activation gate.
Negotiation reports `message_schema_generation`. Storage generation remains **1**;
media metadata advances the wire application layer to **5** and changes the
descriptor fingerprint. Generation-zero stores are refused with
`SchemaResetRequired`; no migration is performed.

Generated API errors remain in the owned completion JSON body as
`{code,name,message,details}` (including target-not-found/deleted, edit-conflict,
not-authorized and schema-reset-required). Their numeric namespace is independent
of C ABI return statuses; the latter map to the existing broad failure categories.

The generated mutation carrier currently uses local gateway routes. A group member
that requires a federated generated carrier receives a typed per-target
`not_connected` failure; the SDK has no generated federation producer today.
It never substitutes the generation-zero carrier. Native generated-carrier tests
verify the actual envelope, pair crypto, receiver commits, source projection
updates and erasure, independently of the production generation-zero gate.


## Bundled card trust package

`ramflux_v2_card_trust_package(out)` returns owned public JSON even before an account
or renderer opens. It includes the bytecode, exact canonical signed descriptor,
Ed25519 signature/public key (binary fields encoded as unpadded base64url), exact
release policy, and complete `en`/`zh-CN` × light/dark host presentations. Free the
buffer with `ramflux_v2_buffer_free`. Package sources live next to the SDK header
in `include/card/`; only public release material is distributed.

This SDK release uses shared library identity `app_id:ramflux.native`,
`package_id:ramflux.card.library`, security epoch 1 and version 1. These are the
shared renderer release identities; they confer no account or SDK authority.
The signed library manifest is `library.descriptor.json`, authenticated by
`library.sig`. The surrounding `trust.json` is a public release index, not a
second signature format. Presentation and policy are host-owned configuration,
separate from signed bytecode and from peer input.

Native application releases independently pin the index BLAKE3 (advertised as
`card_runtime.trust_manifest_blake3`), trusted key and exact descriptor policy.
Load these bundled app/SDK assets rather than a peer-supplied package's policy or
key. Pass the unchanged canonical descriptor bytes, decoded binary material and
separate policy/presentation spans to standalone ABI 4. Preserve host presentation
across peer updates and apply presentation mutation batches normally. Approval
facts, confirmation and Allow/Deny controls remain host-owned outside the tree.

Release tooling runs the existing `card-pack` compiler/signer against the reviewed
library, with a private seed outside the repository. Then run
`scripts/generate-c-abi-card-trust.py` to generate the independently configured
policy and public index; `--check` rejects artifact/catalog/index drift. Never put
a private seed in the package or derive release policy from runtime peer data.


## Native panic and admission contract

Build native libraries with `cargo build --profile ffi-release -p ramflux-sdk
--features card-runtime` (or `c-abi` without cards). This profile inherits release
optimization and uses `panic=unwind`. V2 refuses `panic=abort` builds at compile
time. Existing packaging paths may instead set `CARGO_PROFILE_RELEASE_PANIC=unwind`
with `--release`. Every v2 C entry point contains Rust unwinds; fallible calls report code 17.
Void buffer destruction contains unwinds but cannot report a status. Normal errors
remain typed Results; no production error path intentionally panics. This boundary
does not make invalid host pointers or foreign callback unwinds valid.

The native bridge admits only explicitly classified SDK methods. `daemon.stop`
and test-only methods are denied; use `client_close` to shut down. Negotiation
omits denied methods, and method policy rows expose `bridge_allowed`. Raw routing
still requires `allow_raw_messages:true`. Only policy rows with `key_export:true`
require the explicit trusted-host config capability `allow_secret_exports:true`;
SDK authorization and custody checks apply independently. An operation key is
nonempty and at most 256 UTF-8 bytes. Conversation send persists an intent
fingerprint in account operation metadata before routing; changed conversation,
text or media cannot reuse a key, including across restart or message erasure.
No plaintext send content is retained in that fingerprint record.

Subscription close acknowledgement releases the bridge slot. Failed opens release
the slot too. The C layer discards generation-zero, inactive and stale-generation
events both on enqueue and poll; bindings still compare generations defensively.
Close retries and release use nonblocking completion-state locks; only the initial
close waits for its documented deadline.

Native error envelopes contain codes, effects and structured details without
English diagnostic messages or SDK Display strings. User message/card content is
preserved. Hosts own localization. V2 outputs allocate their final boxed storage
before copying secrets and zeroize temporary buffers. Always free them using
`ramflux_v2_buffer_free`; v1's `ramflux_buffer_free` does not erase secret bytes.

PR CI executes the real supervisor and generation tests under both `c-abi` and
`card-runtime`, including signed Card rollback/exact-digest refusals, conversation
retry/crypto regressions and both generated-manifest freshness checks.

## Native security corrections

The trusted custody provider is the only ABI seed path. Primary and branch seeds
must never appear in JSON methods, completions or event frames. Android providers
wrap seeds with a non-exportable Android Keystore AES-GCM key (StrongBox when
available) before durable persistence; plaintext storage is forbidden. iOS uses
non-synchronizable Keychain items with
`kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly` with a shared Keychain access
group for the application and notification extension. All callback spans are borrowed
only until return. SDK-owned callback input copies are wiped immediately after
both successful and failed callbacks; load buffers and decoded temporary seeds
are zeroized on every exit. Hosts must wipe their own temporary plaintext copies.

`allow_secret_exports` gates **every** method whose generated policy row declares
`key_export:true`: agent credentials, account backups, group sender
keys, device sync and both show-once calls. The policy column is the authority for
this admission check; there is no per-method exception list.

After status PanicAborted (17), stop using that client, close it off the UI thread,
retain/retry its shutdown state until confirmed, and open a new client. Locks may
be poisoned and in-flight effects are unknown; reconcile operation keys before retry.
Card exports independently contain Rust unwinds; status Engine (4) invalidates the
renderer thread's sessions. The version query is a constant and cannot panic.

ABI input parsing owns and wipes incomplete JSON/string values and performs schema
checks before constructing owned requests. No consuming serde conversion can drop
partially deserialized secrets. Error conversion occurs only at typed SDK envelope
fields, never by recursively matching business object property names. Unknown
error details are omitted; diagnostic prose is never promoted to a display field.

Conversation mutation receipts retain only fingerprint, event identity, accepted
recipient keys, terminal reconciliation and expiry independently of message payloads.
Source edit projection and accepted-target progress commit atomically. Only the
current accepted event's pending payload is reattached after retirement, under its
target's normal erasure ownership. Other pending private payloads are erased, and
later edits/deletion retire the current pending payload too; its receipt then
returns a content-free retired/uncertain outcome without re-allocating or resending.

Send and mutation receipts expire with the account's configured content-retention
TTL and are bounded to 1,024 live rows per namespace. Admission at capacity evicts the oldest terminal
receipt; only an all-pending window refuses new operations. Private pending
rows have the same expiry. After expiry or terminal eviction, old keys have no retry guarantee; hosts
must reconcile history and use fresh operation keys.

The bundled SDK Card release is epoch/version 1/2 on the current catalog. Hosts
must refresh their independently pinned trust-index and exact-descriptor digests
when adopting this SDK commit; ABI majors remain SDK 2 and Card 4.


### Receipt capacity and key exports (policy version 2)

The export permission applies only to `account.export_agent_credentials`,
`account.backup.export`, `group.sender_key.export`, `device.sync.export`,
`account.create.show_once` and `account.custody.show_once`. Ordinary reads and
conversation operations work with the default configuration; `secret_output`
remains confidential-data handling metadata.

Send and mutation receipts each have a 1,024-row limit and the account content
TTL. At capacity, admission evicts the oldest terminal receipt first, including
any leftover private intent. Such eviction ends that operation's retry window.
Pending operations are never evicted for capacity: a window full of pending
receipts returns `RateLimited` until one completes or expires. Successful sends
mark their receipts terminal only after all deliveries are submitted.

## Mobile shared-root and background custody contract

The host provisions storage before calling either v2 open function. `data_root`
is an absolute path to an existing dedicated directory. The bridge no longer
creates a missing root. Unix admission never repairs refused permissions.
On Unix the directory must
belong to the effective process user and have mode `0700`; group/other access,
including world-readable roots, is refused before supervisor startup. A final
symlink or non-directory is refused. Ancestor aliases used by platform container
APIs may resolve normally. Use a stable, host-controlled container: this check
is not a recursive ACL audit or protection against a hostile same-user process
replacing paths during startup. Windows retains its existing owner/DACL checks.

Both open functions clear the output handle before admission. Their synchronous
status is the typed refusal; there is no open error JSON or diagnostic-string
parsing contract:

| Outcome | Status | Host action |
| --- | --- | --- |
| Relative, missing, non-directory or final-symlink root | `InvalidArgument` (1) | Obtain/provision the correct container directory; no automatic fallback. |
| OS path permission denial, foreign Unix owner or Unix mode other than `0700` | `PermissionDenied` (12) | Correct the host provisioning; the SDK does not chmod a refused root. |
| Custody preflight returns locked (provider status 4) | `VaultLocked` (31) | Wait for OS custody availability, then retry; no client or supervisor was started. |
| Other custody preflight failure | Existing mapped SDK status | Keep the refusal; never switch to plaintext or another provider. |
| Another client/process owns this root | `AccountBusy` (18) | Retry only after the owner releases its lease. |

A provider passed to `ramflux_v2_client_open_with_custody` is retained during
admission and preflighted once before filesystem access or supervisor startup,
even for an empty root. Locked custody takes precedence over path admission.
Failure releases that retained context. Preflight must check storage availability
without prompting, creating a key, storing a secret or unlocking a collection.
Report unavailable first-unlock custody as callback status **4**, not missing (1),
corrupt (2), a success with empty bytes, or a panic. Ordinary later custody
operations retain their existing typed operation-error envelopes. An open with
no host provider does not claim to establish mobile custody availability.

### iOS host obligations

Resolve the entitled App Group container with
`FileManager.containerURL(forSecurityApplicationGroupIdentifier:)`, and create a
private SDK subdirectory inside it. The main app and notification service
extension use that same root and the same non-synchronizing Keychain access
group. Never pass the app's ordinary private container or a separate extension
root. The SDK cannot attest App Group membership or Keychain entitlements.

Use `kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly` for background wrapping
keys/items, with `kSecAttrSynchronizable=false`. This class becomes available
after the first OS unlock following restart and stays available when the screen
locks again; it does not migrate to another device. Do not use
`kSecAttrAccessibleWhenUnlockedThisDeviceOnly` for the default background wrap.
Use `NSFileProtectionCompleteUntilFirstUserAuthentication` on the root and all
SDK files, including SQLite databases, WAL/SHM sidecars and newly created files.
The host must verify inherited file protection on a physical device; Unix mode
checks cannot establish the iOS data-protection class.

### Android host obligations

Use a dedicated `0700` directory in credential-encrypted app-private storage,
readable by the application and its FCM service under the same app UID. A
separate service process uses the same path/provider and coordinates ownership;
never make it a public/external-storage directory or give another UID access.
Do not put account data or wrapping records in device-protected Direct Boot
storage. Check `UserManager.isUserUnlocked` before opening; pre-first-unlock
custody must report locked without opening an alternate root.

Wrap secrets with a non-exportable Android Keystore AES-GCM key, with
`setUserAuthenticationRequired(false)` for the default background key. Keep the
wrapped records in credential-encrypted storage: that storage supplies the
first-unlock gate; an auth-free Keystore key alone does not. Do not set
`setUnlockedDeviceRequired(true)` as an after-first-unlock substitute: it
requires the device to be unlocked at the time of use and prevents screen-locked
background decryption. No plaintext key persistence or file-vault fallback.

### Ownership and acceptance boundary

One process owns mutation of a shared root. `ramflux_v2_client_open` and
`ramflux_v2_client_open_with_custody` still take the whole-root lease and the
same-process registry. A second open returns `AccountBusy` (18) and starts no
supervisor. Account database writes take the per-account writer lock and fail
immediately with that same status when another process holds it. A receive that
loses the lock returns before any acknowledgement. An uncommitted write rolls
back with the process. Journal mode and synchronous settings are unchanged.

`ramflux_v2_shared_snapshot(config, config_len, provider, out)` is the
extension read. Config is `{data_root, account_id}`. `provider` is the same ABI v1
OS custody table used by `ramflux_v2_client_open_with_custody`, pointing at the
shared after-first-unlock device secret. It is retained only for this synchronous
call and released before return. Locked custody returns `VaultLocked` (31).
The SDK combines that secret with the existing file secret and opens the device
wrap; it never checks a code, creates a secret, or reinstates a cleared wrap.
App lock or explicit account lock removing that wrap returns `AccountCodeRequired`;
the host must use ordinary account unlock. Missing custody fails closed.
It does not take the whole-root lease or the writer lock, and it does not start a
supervisor. One deferred read transaction returns
`{account_id, direct_message_ids, message_ids}` from the last commit. Output uses
`ramflux_v2_buffer_free`. Session handoff after suspension is out of scope.
`rf root snapshot` and `rf root commit` use the same platform custody binding;
fixture builds require explicit `--itest-memory-vault` selection to share the
fixture daemon's custody. There is no code-only or file-secret-only fallback.

A scratch host can verify root admission, the real supervisor's account read,
provider preflight/locked refusal and retain/release balance. Platform acceptance
still requires nn to measure App Group/access-group entitlement behavior, actual
Keystore use, reboot before/after first unlock, screen-relocked background use,
and file/SQLite sidecar protection. A simulated locked callback proves only the
SDK refusal path.

Platform references: [Apple background Keychain accessibility](https://developer.apple.com/documentation/security/ksecattraccessibleafterfirstunlockthisdeviceonly),
[Apple shared containers](https://developer.apple.com/documentation/foundation/filemanager/containerurl(forsecurityapplicationgroupidentifier:)),
[Android Direct Boot storage](https://developer.android.com/privacy-and-security/direct-boot),
[Android Keystore parameters](https://developer.android.com/reference/android/security/keystore/KeyGenParameterSpec.Builder).

### Phone provisioning and process diagnostics

Both open entrypoints accept an optional `username_directory` object containing
`url` (canonical HTTPS origin), `id`, `public_key` (base64url Ed25519) and
`generation` (positive safe JSON integer). This is an independently provisioned
trust pin, never learned from an unverified reply. Each client's supervisor and
private username authorization ceremony use that same pin. Native clients do
not consult username environment variables. An omitted pin yields
`UsernameDirectoryRefused` / `directory_unavailable`. The `rf daemon` CLI alone
can provision the pin from its `RAMFLUX_USERNAME_CENTER_*` and
`RAMFLUX_USERNAME_TRUST_GENERATION` environment settings.

Both open entrypoints also accept the optional strict object:

```json
{"diag":{"level":"info","process":"app","build_class":"release",
         "max_file_bytes":1048576,"max_files":5,"max_age_days":7}}
```

These are the defaults. Native process values are `app`, `nse`, `fgs`; build
classes are `release`, `beta`, `realrun`; levels are `error`, `warn`, `info`,
`debug`, `trace`. Unknown keys and invalid values are refused. Limits can be
lowered to 4096 bytes / 1 file / 1 day, never raised above the defaults. Without
the explicit `diag-realrun` library feature, `realrun` becomes `release` and
`debug`/`trace` become `info`. Phase 0 never records free-text error messages,
even in real-run builds. Later diagnostic calls and verbose windows are separate.

One SDK-owned writer thread serves the process. The first opened data root owns
`diag/<process>.<epoch_ms>.ndjson`; simultaneous clients share this sink when using its configuration or the default
policy. Default callers join the active process policy without changing it;
this also permits a host to embed a socket supervisor and a native client. A
conflicting explicit process configuration is refused.
After the last client closes, a later open may choose a new root. Each file is
UTF-8 NDJSON with schema `ramflux.diag.v1`, wall and monotonic times, process
sequence, severity, layer, component, event and typed fields. Each line is at
most 2048 bytes; oversized fields are omitted and `trunc:true` is set. Rotation
includes the current file in the file-count budget; age pruning runs at open
and rotation. Files have private permissions. `rf daemon` writes the same
format with process `daemon`, independently of the stderr `RUST_LOG` filter.

Producers use a bounded 2048-record queue and never wait for the writer. Overflow
is reported as `diag.dropped` when another event can be queued. Warning/error
records request immediate flush; other records flush at 16 KiB. Client close
and suspend flush the writer. A hard kill may lose queued or unsynced records;
readers must skip a torn final line. Hosts with a Rust tracing subscriber can
compose `ramflux_sdk::diag::DiagnosticLayer`; the native SDK worker installs its
own scoped layer. Existing SDK trace locations are `trace.<source-line>` events;
free text is discarded or replaced with its length. Only known numeric,
boolean and token fields survive. Account, principal, device, conversation,
group, contact, username, message, envelope, object, operation, node, session
and delivery identifiers become `h:` plus ten lowercase hex characters of
HMAC-SHA-256(key, class || NUL || value). Never log message bodies, file names,
passcodes, recovery words, keys, tokens or contact card payloads at any level.

`diag.key_file` may name an existing host-owned private file outside the data
root containing exactly 32 random bytes (Unix owner and mode 0600 required;
symlinks refused). Provision it in private, non-backed-up app storage and rotate
it every 30 days or when deleting diagnostics. If omitted, the SDK creates a
random process key which is never persisted or exported. Hashes then correlate
only within that writer's lifetime. Durable cross-process key storage remains
an open host contract for DIAGNOSTIC-LOGGING-01 C-3/Q5; Phase 0 introduces no
Keychain or Keystore provisioning API. The file header carries a key epoch,
never the key. Clients must collect `diag/` after a run and scan for secret
canaries before sharing it.

Every nonzero asynchronous completion now has a nonempty typed `name`, `reason`
and `reason_code` at the completion root as well as its error envelope. Existing
business reason tokens survive; errors without finer typed context use their
status name (or `invalid_argument`, `internal_error`, `cancelled`). English
`message` text remains internal. Diagnostic refusal records carry code, name,
reason, effect and variant. Immediate synchronous admission calls still return
an integer according to their existing C signature; the diagnostic sink records
the named admission refusal. A group `message.focus` returns the typed
`unsupported_for_group` refusal; group typing is outside the beta scope.


### Suspend failure recovery

`ramflux_v2_client_suspend` rolls back a failed release by reopening parked files
before returning `StorageFailed` (8). The existing event subscription stays active
when rollback succeeds; pending operations may already have completed as Suspended.
The diagnostic writer records `client.suspend.failed`, name `SuspendFailed`, and
reason `suspend_release_failed`. If reopening also fails, admission stays fenced
and the reason is `suspend_rollback_failed`; no new work is admitted into partially
reopened owners. Call `ramflux_v2_client_resume` after any failed suspend (including
a timeout), check its result, and reopen the event subscription from the last cursor.
Resume needs no unlock prompt. The worker publishes the completed lifecycle state
even if the synchronous caller times out. Normal successful suspend still cancels
the subscription, releases files and stops networking; resume reopens them.
