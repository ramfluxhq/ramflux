# C ABI v2

The default-off `c-abi` feature exports `ramflux_v2_*` alongside the unchanged v1
symbols. Link the SDK static library on iOS and the shared library on Android.
Mobile targets bundle SQLCipher's OpenSSL dependency; their system SDKs do not
provide libcrypto. Desktop target dependencies are unchanged.
The header is generated by cbindgen from the Rust exports into
`$CARGO_TARGET_DIR/include/ramflux_sdk.h`; the reviewed copy is
`crates/ramflux-sdk/include/ramflux_sdk.h`. Define `RAMFLUX_WITH_CARD_RUNTIME`
when building with the optional `card-runtime` SDK feature to include its independently owned
`crates/ramflux-card/include/ramflux_card.h` as well. The `ramflux_card_*` session
symbols belong to that crate; sessions are renderer-thread-affine u64 tokens,
and callback JSON is borrowed only for the synchronous callback. Card events
produce declarative intents; SDK authority validates and signs any send.

## Negotiation and requests

Call `ramflux_v2_negotiate(2, 0, &buffer)` before opening a client. Negotiation
returns the binding major/minor, BLAKE3 fingerprint of the message descriptor,
carrier protocol, operation inventory and limits. Binding version and message
schema version are independent. A major mismatch or a newer minimum minor
returns UnsupportedVersion (3). A host must compare the descriptor with the one
its typed message binding was built against.

`client_open` accepts I-JSON `{ "data_root": "/absolute/private/path",
"builtin_nodes": [] }`. It creates one current-thread supervisor and acquires
the existing data-root writer lease. A second opener of that root fails. No
pathname listener is created, and neither the CLI nor its daemon is modified.
Opening and closing block: invoke them on a native background executor.

`execute` copies this bounded request and returns an operation handle immediately:

```json
{
  "account_id": "local-account",
  "sdk_api": "account",
  "method": "account.status",
  "body": {},
  "deadline_ms": 1794571200000,
  "operation_id": "caller-owned-durable-operation-key"
}
```

`account_id` and `operation_id` may be absent. `deadline_ms` is required and is
absolute Unix milliseconds. `body` is the existing SDK bus method's request
body; it is not a second business schema. Message ProtoJSON retains its own
schema's presence and decimal string rules. The bridge never generates an
operation key, retries a mutation or turns a lost response into success.

## Generated method policy

`crates/ramflux-sdk/include/ramflux_sdk_methods.json` is the machine-readable
native binding policy. Each row has `name`, `capability`, `secret_input`,
`secret_output` and `show_once`. Capability is the SDK operation namespace used
for discovery, **not** an authorization grant. Secret flags conservatively mark
confidential payloads/credentials; they never authorize logging other bodies.
`show_once` describes the SDK's one-time phrase-disclosure operations.

The source of truth is the explicit Rust registry
`src/c_abi/v2/method_policy.rs`. Run
`python3 scripts/generate-c-abi-methods.py` to regenerate the checked artifact,
or pass `--check` to detect drift. The feature-enabled build also generates the
same file beside the cbindgen header in `$CARGO_TARGET_DIR/include/`.
`every_operation_has_explicit_policy_and_generated_manifest_matches` compares
policy names against the live SDK method table, custody operations and backup
job methods, and compares all flags with the generated JSON. A new operation
without a policy row fails this test. Negotiation includes this same manifest
under `method_policy`, with `policy_version = 1`.

## Operations

The negotiation inventory comes from the SDK's shared method table plus its
connection-local custody ceremonies. Every admitted request passes through the
same connection dispatcher and supervisor used by the CLI, including authority,
account actors, lifecycle receipts and writer ownership. Integration-fixture
methods are rejected. Operations currently cover:

| Family | Existing shared methods |
| --- | --- |
| Accounts and recovery | `account.list/status/switch/unlock/lock`, `account.create.begin/show_once/hidden_challenge/confirm/cancel`, `account.recover.begin/confirm/cancel` |
| Nodes | `node.list/add/probe/confirm/remove/set_default/set_enabled` |
| Conversations/messages | `conversation.list/directory/mute/disappearing.*`, `message.list/read/submit/delete/receipt.*`, `message.franking_evidence` |
| Contacts/requests | `contact.list/add/request/accept/block/unblock/remove`, `contact.requests.*`, `contact.request.*`, verification/card methods |
| Groups | `group.list/create/history/members/role.set/owner.transfer`, invitations and membership methods |
| Voice | `call.invite/answer/reject/hangup/list/media.session` |
| Agents and permissions | `bot.list/install/revoke/trust.add`, `mcp.*`, `grant.*`, `task.*` |
| Devices/backup/settings | `device.list/pair.*/activate/authorize/revoke/refresh/sync.*`, `account.backup.*`, `account.config.get/set` |
| Attachments/cards | `object.*`, `surface.list/get/send/action/request_resync/resync`, `a2ui.render/action`, `a2i.*` |

This inventory exposes existing business capabilities. It does not assert that
missing core APIs exist: local full-text search, dedicated Agent CRUD/configure,
stranger report/batch flows, and unified edit/reaction/reply methods need their
shared supervisor implementations before they can be advertised as supported.
Edit/reaction/reply enter this inventory once their shared SDK module lands;
the bridge does not implement parallel business handlers.
Card interpreter sessions are owned by the card-runtime module and must be
linked with the SDK in the same mobile library; surface operations here are the
SDK's existing surface delivery operations.

## Completion, cancellation and ownership

Handles are opaque nonzero `uint64_t` tokens; they are never addresses. There
are at most 16 open clients and 64 retained operations per client. Every
operation owns terminal reply credit independent of the event queue.
`operation_poll` returns Pending (24) with a null buffer, or 0 and a JSON
completion `{ "code": 0, "response": <complete SDK response frame> }`.
A nonzero completion `code` is a business failure; the original response error,
reason, details and retry hints remain intact. Polling does not consume a
completion; call `operation_release` exactly once after inspecting it.

The operation token is also its explicit cancellation handle. `operation_cancel`
marks a cancelled waiter. If cancellation wins the locked admission transition,
the worker emits `{ "code": 25, "effects": "none" }` without writing the
request to the dispatcher. After carrier admission, cancellation does not stop
or roll back execution; poll for its result, or release the waiter and reconcile
the original operation key. Lifecycle work and receipts remain supervisor-owned.
Release detaches the native waiter; admitted work retains internal credit until
its terminal response. Discarding a Swift Task or Kotlin Job is not cancellation.

Each nonnull output is a `RamfluxBuffer` owned by the caller. Read exactly `len`
bytes, then call `ramflux_v2_buffer_free` exactly once, including for errors and
secret ceremony responses. It erases the allocation. Do not use the v1 free
function for v2 output. Input remains caller-owned and valid until the FFI call
returns. Temporary encoded requests and retained completions are erased on drop.

`client_close` stops admission and asks the owner thread to disconnect, drain
its supervisor, close stores and release the writer lease. Call it off the UI
thread. The first call waits up to ten seconds and returns Timeout (10) if the
owner has not confirmed completion. The handle and operation completions remain
valid. Further calls poll the retained shutdown state: Pending (24), confirmed
Done (0), or the same cached terminal SDK error. New execution is refused once
close begins, and the real data-root lease refuses a replacement writer while
shutdown is pending. Only confirmed success removes the handle automatically.
Repeated close after confirmed success is harmless.

A terminal shutdown failure remains available on the same handle; after the
host has inspected/reported it, `client_release` explicitly discards the retained
handle and completion state. It returns Pending (24) and retains the handle if
shutdown is unfinished. It never interrupts the supervisor or grants ownership
to a replacement. Stop submissions and event pumps before closing; a lost reply
still has unknown business effects.

## Events and errors

The cbindgen header declares `int32_t ramflux_v2_event_reset(uint64_t handle, uint64_t subscription_generation)`.
It clears the latched gap and buffered stale events for that generation after
the host has rebuilt its projections. A stale generation returns
InvalidArgument (1) and leaves the replacement queue intact. Use 0 only before
the first successful subscription. Cancel the old subscription, await an explicit
`subscription.close` acknowledgement, read the snapshot, reset, then subscribe
from that snapshot's journal cursor. Reset does not fetch data or restore a
subscription by itself.


Open a subscription via `execute` using `subscription.open` or `bus.subscribe`.
`event_poll` consumes one frame without blocking. It returns Pending (24),
Closed (26) with a null buffer. ResyncRequired (27) includes an owned, generation-tagged gap event. Event
credit is bounded to 64 frames and 4 MiB; a single frame is at most 1 MiB.
Overflow clears stale events and latches ResyncRequired. Cancel the old subscription and read current projections, call
`event_reset(handle, old_generation)`, then subscribe from the snapshot's journal cursor; never treat
a gap as a continuous stream. The subscription operation token is its cancellation handle: cancel/release sends
`subscription.close` through the shared dispatcher. Each client owns one active
subscription; cancel it before opening another. Closing also cancels it.
Completions continue independently when event credit is exhausted.

Immediate statuses use existing numeric `RamfluxErrorCode` values 0–23,
including AccountBusy=18 and SchemaResetRequired=23. V2 adds Pending=24,
Cancelled=25, Closed=26 and ResyncRequired=27 without changing v1. Unknown
business error names map to Internal=16 while preserving the full typed SDK
error frame. Native code must inspect numeric codes, not diagnostic prose.

Host pointers must be aligned and valid for their documented lengths. Null,
invalid lengths, duplicate I-JSON members and invalid handles are rejected.
Foreign callers must never pass dangling pointers or double-free buffers.

## Subscription generations

Each successful `subscription.open` / `bus.subscribe` completion carries
`subscription_generation` both beside `code` and in its original response
frame. Every event frame carries the same field. It is an exact decimal JSON
string representing a nonzero u64. Allocation is process-wide, so each
account's generations strictly increase across close/reopen (gaps are valid).
Zero means there was no matching subscription and must never be presented.

The dispatcher snapshots the generation into each outbound producer. Cloned
old producers retain their old generation even if they enqueue after a newer
open completes. All producers still share the original bounded 64-frame queue;
there are no additional per-generation queues. **Hosts drop frames whose
generation != current**, and still validate the expected account. Adopt a new
generation only from a successful open completion. Reset carries the generation
as its second C argument; an old callback cannot clear a newer subscription.

A successful reopen discards old buffered events and the old overflow latch.
Late old events remain tagged old. Overflow caused by a stale frame cannot
invalidate the replacement stream. ResyncRequired (27) returns an owned,
tagged `stream.lagged` event buffer; free it with `ramflux_v2_buffer_free` even
though the status is nonzero. Pending/Closed return null buffers.

`real_dispatcher_preserves_old_generation_after_close_and_reopen` opens the
actual supervisor backup stream, closes/reopens it, then delivers through an
old producer and the real wire writer/decoder. `stale_event_reset_cannot_clear_a_replacement_subscription`
checks the C ABI open completions and rejects a stale reset after reopening.

## Shared client projections

`ramflux_v2_conversation_project(input, len, &out)` calls
`ramflux-client-model::conversation::{page,totals}`. Input is a host-owned
snapshot: `rows` (id, title, optional preview/pinned/latest_ms/unread/attention),
`visible`, optional `query`, `offset` and `limit` (default 100). Output has the
projected rows, `next_offset` and snapshot `totals`. Locked/inaccessible snapshots
set `visible:false`; the shared model clears rows and totals. Its page limit is
100, query limit 1024 bytes; the binding also bounds input to 4096 source rows
and the common frame/value budget. List filtering remains a pure projection.

`ramflux_v2_receipt_present(input, len, &out)` calls the shared receipt
`present()`. Input has `outgoing`, `now_ms` and `receipt`, for example
`{"outgoing":true,"now_ms":"123","receipt":{"state":"sent"}}`.
States are sending, waiting_for_node (retry_at_ms), failed (retryable), sent,
delivered, read. Output is null for incoming messages, otherwise receipt,
manual_retry and remaining_ms. Acceptance never becomes delivery/read because
of time; uncertain outcomes never gain retry permission.

Clocks/offsets accept exact decimal strings (safe JSON numbers are also
accepted); u64/i64 output quantities use decimal strings. Both entrypoints run
without a client handle, use the common buffer ownership/error contract, and
serialize confidential snapshot data. They retrieve no data and confer no SDK
authority. Business models and policy stay in the shared crate.

## Conversation send

Use `conversation.send` through `ramflux_v2_execute`, with an account id, a durable
`operation_id`, and body `{conversation_id,text,attachments?}`. Text is UTF-8, at
most 65536 bytes; an empty text requires an attachment. Routing fields are refused.
The SDK derives the sender from its authenticated device, the peer commitment from
the existing conversation, and recipient devices from the verified manifest. Group
conversations use the ordinary group sender. Sealing, friend-link checks, TTL,
own-device copies and gateway submission use the existing SDK delivery paths.
Group attachments retain the existing SDK limitation and are refused.

The call returns the usual asynchronous operation handle. Its completion body has
`message_id`, `conversation_id`, `delivery_state` (`submitted` or `failed`), and
per-target `deliveries` with stable error codes on failure. Submitted means gateway
submission, never delivery or read. Use existing receipt/event projections for later
progress. Fan-out preserves the first local ciphertext and refuses a changed sender,
conversation or plaintext under that logical id. Raw SDK sends retain their existing
ciphertext collision fence. The logical message id is derived from account and operation id, so retries
retain identity. Existing operation reconciliation governs interrupted mutations;
a failed fan-out can have partial effects and is not a no-effects cancellation.
Before a verified route is available the operation can return the usual SDK error.

`message.submit` is disabled in v2 by default (PermissionDenied=12 before admission).
Trusted diagnostic hosts can open with `allow_raw_messages:true`; its generated
capability is `raw_message`. Native product clients use `conversation.send`.

## Host custody provider (Android M4 and iOS)

`ramflux_v2_client_open_with_custody` accepts the same JSON config plus a version-1
`RamfluxV2CustodyProvider` table. It adapts host OS storage to the SDK's existing
`PrimaryVault`; account create/recovery/pairing remain SDK ceremonies. M4 supplies
Android Keystore wrapping and JNI attachment on callback threads. An iOS host can
supply Keychain storage through the same seam. Ordinary open keeps the existing
native provider selection; there is no file or data-passphrase fallback.

The provider must be non-synchronizing, device-local and independent of data unlock.
Primary and branch entries are separate. Store operations are create-only, refuse
an existing reference, and complete only after durable protected storage; delete is
idempotent. References are opaque canonical SDK references, not filesystem paths.
The provider's preflight runs before recovery material is shown. This seam grants
no independent user-presence authorization: migration signing remains fail-closed.

The header defines operations and callback status values. Primary bytes are a
32-byte vault seed; branch bytes are 64-byte signing/agreement seeds; provisioning
bytes are bounded to 4096. Store inputs and load outputs are secret and must never
be logged, persisted in ordinary preferences, or exposed to application observers.
All callback buffers are borrowed for the synchronous invocation only. The SDK owns
and erases its output buffers; hosts must erase temporary copies. Output lengths
are validated before decoding and key lengths must match exactly.

The table is copied during open. All callbacks are mandatory and may run on SDK
worker/blocking threads, including concurrently; attach to the host runtime as
needed. Callbacks must be bounded, must not unwind, and must not reenter this client.
`retain(context)` occurs once after table validation; `release(context)` occurs
once after the final SDK task drops the provider, including failed startup or a
shutdown that initially timed out. Keep callback code loaded until release. Pending
close retains context; confirmed successful close has drained its tasks. Context is
an opaque 64-bit host token; the SDK never dereferences it.

## Optional renderer linkage

Build `ramflux-sdk --features card-runtime` to include the accepted `ramflux-card`
rlib and its C exports in the SDK library. This enables SDK `c-abi` as well;
ordinary `c-abi` builds omit the renderer. Package one Rust library and both
headers, and define `RAMFLUX_WITH_CARD_RUNTIME` when consuming the umbrella header.
Negotiation returns `card_runtime:null` when disabled, otherwise the independent
card ABI major and catalog SHA-256. Always check `ramflux_card_abi_version()`
before passing card structures. The accepted runtime currently uses card ABI 2;
SDK ABI 2 numbering is independent. Unaccepted ABI3 library changes are not linked.

`RamfluxCardOpen.descriptor` authenticates application/package identity, catalog,
engine, ABI, epoch/version and exact bytecode digest. Its separate `policy` and
trusted key come from the embedding application's pinned release configuration,
never peer/package input. All card calls remain on their creating renderer thread;
callback bytes are borrowed only during the synchronous callback. Card statuses
remain their own 0..8 namespace. Declarative intents confer no SDK authority.
