# C ABI v2

The default-off `c-abi` feature exports `ramflux_v2_*` alongside the unchanged v1
symbols. Link the SDK static library on iOS and the shared library on Android.
The header is generated by cbindgen from the Rust exports into
`$CARGO_TARGET_DIR/include/ramflux_sdk.h`; the reviewed copy is
`crates/ramflux-sdk/include/ramflux_sdk.h`.

## Negotiation and requests

Call `ramflux_v2_negotiate(2, 0, &buffer)` before opening a client. Negotiation
returns the binding major/minor, BLAKE3 fingerprint of the message descriptor,
carrier protocol, operation inventory and limits. Binding version and message
schema version are independent. A major mismatch or a newer minimum minor
returns UnsupportedVersion (3). A host must compare the descriptor with the one
its typed message binding was built against.

`client_open` accepts I-JSON `{ "data_root": "/absolute/private/path",
"builtin_nodes": [] }`. It creates one current-thread supervisor and acquires
the existing data-root writer lease. A second opener of that root fails. No
pathname listener is created, and neither the CLI nor its daemon is modified.
Opening and closing block: invoke them on a native background executor.

`execute` copies this bounded request and returns an operation handle immediately:

```json
{
  "account_id": "local-account",
  "sdk_api": "account",
  "method": "account.status",
  "body": {},
  "deadline_ms": 1794571200000,
  "operation_id": "caller-owned-durable-operation-key"
}
```

`account_id` and `operation_id` may be absent. `deadline_ms` is required and is
absolute Unix milliseconds. `body` is the existing SDK bus method's request
body; it is not a second business schema. Message ProtoJSON retains its own
schema's presence and decimal string rules. The bridge never generates an
operation key, retries a mutation or turns a lost response into success.

## Operations

The negotiation inventory comes from the SDK's shared method table plus its
connection-local custody ceremonies. Every admitted request passes through the
same connection dispatcher and supervisor used by the CLI, including authority,
account actors, lifecycle receipts and writer ownership. Integration-fixture
methods are rejected. Operations currently cover:

| Family | Existing shared methods |
| --- | --- |
| Accounts and recovery | `account.list/status/switch/unlock/lock`, `account.create.begin/show_once/hidden_challenge/confirm/cancel`, `account.recover.begin/confirm/cancel` |
| Nodes | `node.list/add/probe/confirm/remove/set_default/set_enabled` |
| Conversations/messages | `conversation.list/directory/mute/disappearing.*`, `message.list/read/submit/delete/receipt.*`, `message.franking_evidence` |
| Contacts/requests | `contact.list/add/request/accept/block/unblock/remove`, `contact.requests.*`, `contact.request.*`, verification/card methods |
| Groups | `group.list/create/history/members/role.set/owner.transfer`, invitations and membership methods |
| Voice | `call.invite/answer/reject/hangup/list/media.session` |
| Agents and permissions | `bot.list/install/revoke/trust.add`, `mcp.*`, `grant.*`, `task.*` |
| Devices/backup/settings | `device.list/pair.*/activate/authorize/revoke/refresh/sync.*`, `account.backup.*`, `account.config.get/set` |
| Attachments/cards | `object.*`, `surface.list/get/send/action/request_resync/resync`, `a2ui.render/action`, `a2i.*` |

This inventory exposes existing business capabilities. It does not assert that
missing core APIs exist: local full-text search, dedicated Agent CRUD/configure,
stranger report/batch flows, and unified edit/reaction/reply methods need their
shared supervisor implementations before they can be advertised as supported.
The independent message-unification branch is not a dependency of this branch.
Card interpreter sessions are owned by the card-runtime module and must be
linked with the SDK in the same mobile library; surface operations here are the
SDK's existing surface delivery operations.

## Completion, cancellation and ownership

Handles are opaque nonzero `uint64_t` tokens; they are never addresses. There
are at most 16 open clients and 64 retained operations per client. Every
operation owns terminal reply credit independent of the event queue.
`operation_poll` returns Pending (24) with a null buffer, or 0 and a JSON
completion `{ "code": 0, "response": <complete SDK response frame> }`.
A nonzero completion `code` is a business failure; the original response error,
reason, details and retry hints remain intact. Polling does not consume a
completion; call `operation_release` exactly once after inspecting it.

The operation token is also its explicit cancellation handle. `operation_cancel`
marks a cancelled waiter. If cancellation wins the locked admission transition,
the worker emits `{ "code": 25, "effects": "none" }` without writing the
request to the dispatcher. After carrier admission, cancellation does not stop
or roll back execution; poll for its result, or release the waiter and reconcile
the original operation key. Lifecycle work and receipts remain supervisor-owned.
Release detaches the native waiter; admitted work retains internal credit until
its terminal response. Discarding a Swift Task or Kotlin Job is not cancellation.

Each nonnull output is a `RamfluxBuffer` owned by the caller. Read exactly `len`
bytes, then call `ramflux_v2_buffer_free` exactly once, including for errors and
secret ceremony responses. It erases the allocation. Do not use the v1 free
function for v2 output. Input remains caller-owned and valid until the FFI call
returns. Temporary encoded requests and retained completions are erased on drop.

`client_close` stops admission, disconnects the carrier, drains the supervisor,
closes stores and releases the writer lease. It is idempotent. A native caller
must stop pumps before closing; concurrent lookups retain their state safely.
Closing can wait up to ten seconds for the existing supervisor shutdown. Failure
returns a code while the owner thread continues shutdown; it does not authorize
a replacement writer. Closed/lost replies have unknown effects.

## Events and errors

Open a subscription via `execute` using `subscription.open` or `bus.subscribe`.
`event_poll` consumes one frame without blocking. It returns Pending (24),
Closed (26), or ResyncRequired (27) with a null buffer when applicable. Event
credit is bounded to 64 frames and 4 MiB; a single frame is at most 1 MiB.
Overflow clears stale events and latches ResyncRequired. Cancel the old subscription and read current projections, call
`event_reset`, then subscribe from the snapshot's journal cursor; never treat
a gap as a continuous stream. The subscription operation token is its cancellation handle: cancel/release sends
`subscription.close` through the shared dispatcher. Each client owns one active
subscription; cancel it before opening another. Closing also cancels it.
Completions continue independently when event credit is exhausted.

Immediate statuses use existing numeric `RamfluxErrorCode` values 0–23,
including AccountBusy=18 and SchemaResetRequired=23. V2 adds Pending=24,
Cancelled=25, Closed=26 and ResyncRequired=27 without changing v1. Unknown
business error names map to Internal=16 while preserving the full typed SDK
error frame. Native code must inspect numeric codes, not diagnostic prose.

Host pointers must be aligned and valid for their documented lengths. Null,
invalid lengths, duplicate I-JSON members and invalid handles are rejected.
Foreign callers must never pass dangling pointers or double-free buffers.
